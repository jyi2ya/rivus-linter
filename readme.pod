LLM 很懒而且很笨。需要很多约束才能让它们写出看得过去的代码。

但是 LLM 又很聪明且很勤快，不管多长多无聊的代码它都能写得下去。

所以需要这个项目来指导 LLM 的行为，并检查生成的代码。结合 clippy 之类的工具，确保 LLM 一直走在最佳实践的路上。

=head1 开发状态

C<cargo-rivus> 仍在积极开发，存在许多已知和未知 bug，也可能误报或漏报。

如果 LLM 认为某个诊断、能力传播、推断结果或工具失败可能是 linter 的 bug，必须立即停止当前工作并向人类汇报，等待进一步决定。不得修改业务代码来迎合可疑诊断，也不得通过改名、添加能力后缀、修改 capsmap、添加 C<allow>/C<suppress>、降低检查级别、重构或其他 workaround 绕过它。

=over

=item 1. 安装 C<cargo-rivus> 二进制并放到 C<$PATH> 中。

=item 2. 在项目中运行 C<cargo rivus setup>

=item 3. 在 LLM 交付时运行 C<cargo rivus>，并根据结果训斥它们。

=back
