# World 端口与长期资源

外部世界中的操作由两部分组成：解释操作的规则，以及操作发生时所处的世界。
规则本身没有运行时身份，不需要被包装成对象；世界保存运行所需的状态，并由调用方
明确维护其生命周期。

一个 World 端口必须声明且只声明一个名为 `World` 的世界类型。端口至少包含一个操作，
操作不以端口对象为接收者，而是显式接收该世界的只读或可变引用。端口名称不决定它
是否是端口。

端口可以声明额外的关联类型来表示长期资源，例如连接、流或事务。资源由某个端口操作
创建，由调用方在多次操作之间持有，并由终止操作消费。资源的具体表示属于解释器；
调用方只能移动资源或把它交回同一个端口，不能依赖其内部结构。普通观察结果和领域错误
不是实现细节，必须使用端口契约中的具体数据类型，不能用关联类型隐藏。

长期资源具有真实身份，因此调用方必须决定它的作用域以及对哪个资源执行操作。正常终止
应当显式消费资源；异常退出时可以由资源自身提供最低限度的回收。资源所有权是被建模的
事实，不应通过无身份的 Client、Repository 或服务对象间接隐藏。

World 端口操作始终包含 `P`，但它自身的完整契约不固定为只有 `P`。各解释器实现的
`B/I/S/T` 能力按普通 trait 的至少半数规则逐项投票，入选能力进入操作契约和函数后缀；
`A/C/M/U` 仍由操作自己的签名与安全事实决定，但只有 BIMPST 字母进入后缀。解释器实现和默认实现向下调用其他函数时，
按这个完整契约检查，因此只有契约已经声明的环境效果才能被实现。

调用方看到的是端口边界而不是解释器效果：只要被调用操作的完整契约包含 `P`，该调用边
向上传播的能力就折叠为仅 `P`，不再传播同一契约中的 `B/I/S/T`。未知调用和不安全访问仍须
报告。这样完整契约可以是 `BIPS`，实现体可以合法执行阻塞 I/O 和副作用，而上层编排函数
仍只声明自己依赖 `P`。

同一个具体 World 可以由多个端口共同解释。调用方通过它声明依赖的端口集合获得操作权限，
而不是获得对 World 内部所有资源的直接访问。由此，World 不能退化为核心代码可随意读取的
服务定位器。

带接收者的方法、没有显式 World 参数的操作、没有操作的 trait、泛型 World 和 associated
constant 都不构成 World 端口。它们按普通 trait 处理。依赖库中的结构相同 trait 也不能仅凭
形状获得当前项目的端口权限；端口约定只作用于当前分析认定的本地代码。
