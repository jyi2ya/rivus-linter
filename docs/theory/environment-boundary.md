# 环境边界

Rivus 的核心负责解释源码事实和能力规则。文件系统、进程、环境变量、
Cargo 调用、平台差异、缓存、迁移、发布、恢复和兼容处理都属于环境适配，
不是 lint 规则的一部分。

核心包含：

- HIR 事实收集和诊断规则
- 函数图、能力模型和推断
- artifact 与 caps 数据模型

环境层包含：

- 文件和目录操作
- 子进程与 Cargo/rustc 调用
- 环境变量和平台 API
- setup、迁移、缓存、锁、发布、回滚和清理
- CLI 命令编排与源码写回

依赖方向只能从入口和环境层指向核心。核心不能为了处理环境异常而引入
文件系统、进程或平台状态。需要环境数据时，由环境层先读取并转换为明确的
核心输入；核心返回决定或结构化结果，再由环境层执行副作用。

核心确实需要跨多次操作持有外部资源时，通过 World 端口取得不透明的 associated resource。
解释器类型没有运行时对象；World 保存环境状态，resource 表示具有真实身份和生命周期的
连接、流或事务。完整规则见 `world-ports.md`。

图诊断的渲染属于环境适配：核心的离线引擎只产生结构化诊断——类别、固定 severity
和锚定 identity；把锚定解析为源码位置并呈现给用户（父进程渲染适配器直接消费
artifact 源码记录，不经 rustc 管线）是环境层的职责。核心不感知渲染器选择。
